## 0. 2026-09-26：阶段 1 融合关系结构失真诊断

当前研究暂时从继续增加 UniGIR 模块转为先验证现象。固定 G0 的 InfMasking checkpoint，只在测试时改变 token masking ratio，使用同一批 256 个 pair 和 5 个 mask seed，测量完整融合表示关系矩阵与 masked 融合表示关系矩阵的 Spearman 相关、Top-5/10/20 邻居保持率和 full-mask cosine。

这一阶段直接测量的是融合表示关系结构，只能作为全局协同结构的代理指标。它不能直接证明真正的 synergy structure 发生变化。详细协议、输出文件和停止条件见 [`25_阶段1融合关系结构诊断计划.md`](25_阶段1融合关系结构诊断计划.md)。本阶段不重新训练、不改训练目标、不实现 V4，也不加入新的 prototype、Sinkhorn 或 consistency 模块。

2026-09-19 复核说明：EXP-001 至 EXP-015 使用修复前的原型更新和逐 epoch 测试集 probing，只作为探索实验。修复后的实验从 EXP-017 开始编号，不能与旧结果直接合并。

## 1. 实验原则

1. 先用 CPU 做低成本诊断，确认实现和目标形式，再申请 GPU 做长训练。
2. 每次只改变一个主要因素，保留 seed、数据组和评测方式。
3. 低成本诊断关闭 probing；正式实验固定 epoch，只保存最后 checkpoint，并在 fit 结束后对官方测试集 probing 一次。
4. 每个实验都记录完整配置、日志路径、代码状态和失败原因。
5. 不把单次短训练结果写成最终结论。

### EXP-025：MOSI profile loss weight 三 seed 对照

目的：检查降低 profile 约束强度是否能缓解 G0 中观察到的任务间表征权衡。实验只使用 MOSI，不读取封存的 G0 数据；保持 seed、数据版本、10 epoch、batch size 32、queue=1024、$K=128$、单向 profile 和 `by_fit` probing 不变，只将 $\alpha$ 从 `0.25` 改为 `0.125`。

| model seed | Baseline acc@1/AUC | $\alpha=0.25$ acc@1/AUC | $\alpha=0.125$ acc@1/AUC | $\alpha=0.125-\alpha=0.25$ |
|---:|---|---|---|---|
| 42 | 0.573 / 0.655 | 0.641 / 0.704 | 0.641 / 0.715 | 0.000 / +0.011 |
| 7 | 0.559 / 0.627 | 0.587 / 0.642 | 0.607 / 0.664 | +0.020 / +0.022 |
| 123 | 0.608 / 0.671 | 0.636 / 0.717 | 0.557 / 0.652 | -0.079 / -0.065 |
| 三 seed 平均 | 0.580 / 0.651 | 0.621 / 0.688 | 0.602 / 0.677 | -0.020 / -0.011 |

三个 seed 均以 `EXIT_CODE=0` 完成并生成 checkpoint。$\alpha=0.125$ 仍高于 Baseline，但平均表现低于 $\alpha=0.25$，且 seed=123 明显退化。该对照不能直接解释 G0 unique2，因为 MOSI 没有对应的 texture 任务；它只说明降低 profile 权重没有稳定消除下游任务权衡。后续不再增加 loss weight、queue 或 prototype 组合，转向结果归档和论文材料整理。

在两个 seed 的最后一轮，UniGIR 的 synergy acc@1 和 synergy ROC AUC 都高于 Baseline，平均差异分别为 +0.028 和 +0.020；但 share 在两个 seed 都下降，unique1、unique2 和平均 acc@1 的方向不一致。平均 acc@1 只提高约 0.001，不能认为存在稳定的整体性能提升。

对下一步的影响：两个 seed 支持单向版本在 synergy 上存在弱的、方向一致的信号，但不支持它已经稳定改善整体多任务表现。带决策门的验证路线见第 12 节；先完成协议冻结与短周期 pilot，再做机制对照和 MOSI 预检，不直接进入大规模 GPU 长训练。

## 11. 判断标准

低成本诊断通过的最低条件：

1. 无 NaN，queue 和 EMA 能正常更新；
2. profile_usage_entropy 不快速降到接近 0；
3. profile_active_prototypes 不长期只有极少数；
4. profile KL 能下降或保持稳定；
5. 不同设置之间能观察到可解释的差异。

只有在上述条件满足后，才选择少数设置做 probing。只有在 GPU 长训练和多 seed 中 synergy 稳定高于 Baseline，才把 UniGIR 作为有效方法继续扩展。

正式确认不能只给当前数据换模型 seed。需要使用未参与方法选择的数据 seed 生成一个新的完整数据根目录，并在该数据的 train split 上从头训练 Baseline 与 UniGIR，再评测对应 test split。这样可以避免新 test 中的组合曾经出现在当前训练集。

### 12.3 G1：修复版短周期 pilot

研究问题：修复 EMA、公平随机性和评测协议后，UniGIR 是否仍有可重复的 synergy 信号。

| 项目 | 配置 |
|---|---|
| 数据 | 当前 S 组开发 split，biased=true |
| pair 数 | max_size=1024 |
| 模型规模 | embed_dim=256，num_mask=3 |
| 训练长度 | 固定 10 epoch |
| 模型 seed | 42、7、123 |
| 对照 | M0 InfMasking；M1 UniGIR 单向 |
| UniGIR | $K=128$，queue=1024，$\alpha=0.25$ |
| 评测 | by_fit，最后 checkpoint，训练完成后评测一次 |
| 第一指标 | synergy ROC AUC |
| 保护指标 | synergy acc@1、四任务平均 acc@1、其他三个任务 |
| 诊断 | profile loss、profile KL、prediction usage entropy、target confidence、prototype similarity |

运行顺序：

1. 先运行 seed=42 的 Baseline 和 UniGIR；
2. 核对显存、时间、日志、checkpoint、最终 probing 次数和诊断量；
3. 若没有实现异常，再运行 seed=7、123；
4. 汇总配对变化，不选最好 seed，不挑最好 epoch。

判断规则：

| 状态 | 预先规定的条件 | 后续行动 |
|---|---|---|
| Strong Go | 3/3 seed 的 synergy ROC AUC 提升，平均绝对提升至少 0.01，平均 acc@1 下降不超过 0.01，诊断无退化 | 进入 G2 |
| Weak Go | 至少 2/3 seed 提升，平均变化为正，平均 acc@1 下降不超过 0.01 | 只做优先级最高的 G2 对照 |
| Uncertain | 平均变化为正但只有 1/3 seed 提升，或不同指标冲突 | 检查目标和方差；不扩展完整实验 |
| No-Go | 平均 synergy ROC AUC 不提升，或多数 seed 广泛损害其他任务，或 profile 稳定但下游无变化 | 暂停 UniGIR |

0.01 是 pilot 的工程筛选阈值，用于控制后续投入，不表示统计显著性。三 seed 只能支持方向判断；报告时必须给出每个 seed、均值、标准差和配对差值。

G1 实际结果：seed=42、7、123 的 synergy ROC AUC 变化分别为 `+0.001`、`+0.022`、`-0.016`，2/3 个 seed 提升，三 seed 平均变化约 `+0.002`；四任务平均 acc@1 的平均变化约 `+0.014`。因此达到 Weak Go，未达到 Strong Go。后续只解锁 G2 的最小机制对照，不解锁 100 epoch 长训练或正式未见数据确认。

脚本为 run_scripts/gpu_pilot_s_group.ps1。脚本检测不到 CUDA 时停止，不回退到 CPU 长训练。

### 12.4 G2：机制对照

研究问题：若 G1 有信号，收益是否来自有意义的 global relational profile。

第一轮只在开发 split 和 seed=42 上做最小对照。只有对照结果符合预期，才在 seed=7、123 上复查。

| 编号 | 对照 | 回答的问题 | 支持核心假设的结果 | 否定或削弱核心假设的结果 |
|---|---|---|---|---|
| C0 | 正常 UniGIR | 当前方法的参考结果 | 保持 G1 信号 | G1 信号不能重复 |
| C1 | Shuffled Profile | 轮廓内容是否有用 | 打乱后 profile 或 downstream 明显变差 | 与正常 UniGIR 接近 |
| C2 | queue=0 | 跨 batch 记忆是否有贡献 | 正常 queue 优于 queue=0 | 两者接近或 queue=0 更好 |
| C3 | No Sinkhorn | 均衡分配是否必要 | 去除后原型使用或性能退化 | 去除后不受影响 |

C1 优先级最高，因为它直接区分有意义的关系目标与普通辅助正则。C2 已经等价于当前实现中的 batch-only profile。现阶段不能把 No Queue 和 Batch-only 写成两项独立消融。C3 只在 C0、C1、C2 给出支持后再运行。

G2 的通过条件：

- 正常 UniGIR 的 downstream 信号可以重复；
- shuffled profile 明显削弱至少一个预先规定的核心结果；
- profile 指标改善与 downstream 变化具有一致方向；
- 结果不能仅由 Sinkhorn 强制均衡解释。

若 shuffled profile 与正常 UniGIR 接近，当前关系轮廓解释不成立，应先重写目标或停止该候选，不进入完整长训练。

G2 实际结果：C1 shuffled profile 在 seed=42 上使 unique1 ROC AUC 下降 0.071、synergy ROC AUC 下降 0.045，给出样本对应关系有用的部分证据；C2 queue=0 使四任务平均 acc@1 下降 0.025，但 synergy ROC AUC 上升 0.050，说明 queue 对整体表示有帮助，却不是当前 synergy 信号的必要条件。由于两项都只有一个 seed，且最终日志未记录 profile accuracy 等诊断量，G2 暂记为 Uncertain。后续不再增加 Trifeatures 机制变体，先做 MOSI 数据和 loader 的离线预检。
