## 三、UniGIR V2 方法

### 3.1 基本想法

InfMasking 的原有目标是让完整视图和掩码视图保持足够的信息联系。UniGIR V2 在此基础上增加一个全局关系轮廓：把完整视图的表示分配到一组可学习原型上，再要求掩码视图预测完整视图的原型分配。

设完整视图表示为 $z^{f}$，掩码视图表示为 $z^{m}$，原型集合为 ${c_k}_{k=1}^{K}$。完整视图先得到原型分配 $q^{f}$，掩码视图得到预测分布 $p^{m}$，profile 损失写为：

$$
\mathcal{L}_{\mathrm{profile}}
=
-\sum_{k=1}^{K}q^{f}_{k}\log p^{m}_{k}.
$$

当前使用单向预测，即掩码视图预测同一增广下完整视图的原型分配。cross 版本还会加入跨增广预测，目前只作为对照，没有作为主要配置。

### 3.2 Sinkhorn 原型分配

如果直接使用普通 softmax，所有样本可能集中到少数几个原型。为避免这个问题，我使用 Sinkhorn 对完整视图的原型分配进行均衡化，使一个 batch 中的原型使用更均匀。由于 target usage entropy 和 active prototypes 会被 Sinkhorn 直接推向均匀，当前还同时记录预测分布熵、目标置信度和原型平均绝对余弦相似度。

### 3.3 EMA 原型更新

原型不直接参与梯度更新，而是根据当前 batch 的特征分配用指数移动平均更新：

$$
c_k
\leftarrow
\beta c_k+(1-\beta)\,\bar z_k,
$$

其中 $\bar z_k$ 是当前分配到第 $k$ 个原型的特征均值，$\beta$ 是 EMA 衰减系数。这样可以减少原型在短训练中的剧烈变化。

### 3.4 Feature queue

当前 batch 较小时，原型分配只看到少量特征，轮廓不够稳定。feature queue 保存历史 batch 的特征，并在计算原型分配时加入这些历史特征。当前主要候选使用 queue 长度 1024，并用 queue=0 作为消融。

总损失为：

$$
\mathcal{L}
=
\mathcal{L}_{\mathrm{InfMasking}}
+
\alpha\mathcal{L}_{\mathrm{profile}}.
$$

当前主要候选使用 $K=128$、queue 长度 1024、$\alpha=0.25$。这些设置来自低成本诊断，只代表下一阶段的候选配置，还需要在更多 seed 和更长训练中验证。

- 任务：share、unique1、unique2、synergy；
- 主要指标：各任务 acc@1、各任务 ROC AUC、四任务平均 acc@1；
- profile 诊断：profile loss、profile KL、target usage entropy、prediction usage entropy、target confidence、prototype mean absolute cosine、active prototypes、profile accuracy。

### 4.2 本机限制

当前电脑没有可用 NVIDIA GPU，PyTorch 使用 CPU 版本。在 batch size 64、embedding 512、6 个 mask 的配置下，单个训练 step 的反向传播约需 36 秒，完整数据一个 epoch 约需 1.5 至 1.6 小时，加入 probing 后还会继续增加。

因此已经完成的 CPU 实验主要用于三件事：检查代码能否运行，筛选方法配置，观察短训练中的信号。完整数据、100 epoch 和多 seed 的正式验证需要 GPU。

## 六、目前得到的结论

1. InfMasking Baseline 已经在本地 Windows、CPU 和 Trifeatures 数据上跑通，训练、四任务 probing 和 checkpoint 保存均可执行；
2. UniGIR V2 的 Sinkhorn、EMA、feature queue、profile loss 和诊断指标已经通过前向、反向和端到端训练检查；
3. 修复前 profile accuracy 在两个 seed 中都从约 0.3 上升到约 0.7，说明新增分支能够拟合伪标签；旧指标不足以单独判断是否塌缩；
4. queue=1024 比 queue=0 更有利于 profile 分支学习，当前短训练中对 synergy 也有小幅帮助；
5. 两个 seed 都出现 synergy 指标向上的方向，但提升幅度很小；
6. 四任务平均 acc@1 没有形成稳定优势，当前不能把 UniGIR 写成已经确认有效的方法；
7. 现有结果只支持继续做修复版短周期 pilot，尚不足以支持完整 100 epoch 长训练；
8. 当前主要候选为单向预测、$K=128$、queue=1024、$\alpha=0.25$。若 pilot 有信号，优先做 shuffled profile 和 queue=0，再尽快检查 MOSI；
9. 当前 Trifeatures test split 已参与多轮选择，应继续作为开发集。正式结论需要未见的数据 seed；
10. queue=0 在现有实现中已经等价于 batch-only profile，二者不能重复写成两项消融。
