## 7. 运行注意事项

本机 CPU 训练时一次只运行一个 Python 进程。过去出现过两个训练进程同时占用 CPU，表现为训练速度明显下降甚至长时间没有日志。启动前检查：

    Get-Process python* -ErrorAction SilentlyContinue

确认没有残留训练进程后再启动新的实验。完整训练日志和实验结果应分别登记到 03_实验记录.md 和 04_结果分析.md。Windows 控制台可能使用 GBK 编码，诊断脚本已关闭 Rich 进度条，避免训练完成后因特殊字符输出导致进程返回错误。

## 12. Linux SSH 与 Docker 服务器

服务器运行计划单独记录在 `ProjectDocs/12_服务器SSH与Docker运行计划.md`。现有 Windows PowerShell GPU 脚本不能直接在服务器使用，服务器需要 Linux shell 版本，并通过宿主机目录挂载保存代码、数据、运行结果和缓存。

正式运行前依次确认 SSH、Docker 权限、课题组镜像、NVIDIA Container Toolkit、GPU 调度规则和宿主机存储路径。容器内先完成 CUDA 检查、单元测试、Hydra 配置解析和 1 epoch 冒烟，再做 G0 数据固定和 G1 seed=42 配对 pilot。代码、数据、结果和缓存使用独立挂载，训练输出覆盖到 `/workspace/runs`，不写入容器内部。

原始 InfMasking 仓库的官方 README 要求 Linux + Conda + Python 3.8，并提供 `environment.yml` 和 Bash 运行入口。公开仓库没有 Dockerfile 或 Compose 文件。原始环境文件固定 Python 3.8.18、PyTorch 2.1.0、CUDA 11.8、torchvision 0.16.0 和 PyTorch Lightning 2.1.1。服务器优先复用课题组已有的兼容镜像；没有现成镜像时，再基于该环境文件构建并记录差异。Windows uv 环境只用于本地开发和低成本验证。

官方脚本按多个 seed 自动循环，当前服务器流程拆成单 seed、单方法、单 GPU，避免一次占用共享资源。UniGIR 的当前工作区改动必须随代码同步，不能重新克隆官方仓库覆盖这些改动。
