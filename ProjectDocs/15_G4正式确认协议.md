## 1. 目的与边界

G3 在 MOSI 的 10 epoch 单 seed 试验中，UniGIR 相比 Baseline 的 acc@1 提升 0.068，ROC AUC 提升 0.049。这个结果只能说明当前配置下出现了正向信号，不能单独作为最终结论。

G4 用来回答两个问题：

1. MOSI 上的提升是否能在多个模型 seed 下重复出现；
2. 在从未用于开发决策的 Trifeatures 数据上，UniGIR 是否仍然优于 Baseline。

G4 期间不再根据中途结果调整 UniGIR 的温度、队列长度、损失权重、mask 配置或训练预算。若协议执行中发现代码错误，只修复影响运行正确性的错误，并保留原始日志、错误说明和修复后的重新运行记录。

## 2. 实验分为两个阶段

| 阶段 | 数据 | 作用 | 是否用于最终结论 |
|---|---|---|---|
| G3 多 seed 补充 | MOSI，沿用 G3 已确认配置 | 检查真实任务上的 seed 稳定性 | 作为真实数据证据的一部分 |
| G4-G0 正式确认 | 封存的独立 Trifeatures 数据 | 检查方法是否能在未参与开发的数据上保持优势 | 作为主要的合成数据确认结果 |

执行顺序固定为先 G3 多 seed，再执行 G4-G0。G3 多 seed 如果出现明确退化，先记录并停止 G0 长实验；G3 只有在没有明确否定核心假设时，才进入 G0。

## 4. G3 多 seed 补充协议

### 4.1 固定参数

G3 seed 42 已完成，新增 seed 7 和 seed 123。新增实验必须完整沿用 seed 42 的配置：

| 项目 | 固定值 |
|---|---|
| 数据 | MOSI，沿用当前已下载并验证的数据版本 |
| 方法 | Baseline 与 UniGIR 成对运行 |
| 训练 epoch | 10 |
| batch size | 32 |
| embedding dim | 256 |
| mask 数量 | 3 |
| mask ratio | 0.7 |
| UniGIR queue size | 1024 |
| UniGIR prototype 数 | 128 |
| UniGIR loss weight | 0.25 |
| cross 模式 | 关闭 |
| linear probing | 开启，`frequency=by_fit` |
| checkpoint | 每个 epoch 保存独立目录下的 `last.ckpt` |
| model seed | 7 或 123；seed 42 的结果已经完成 |

MOSI 没有 Trifeatures 的 pair sampling 过程，因此这里没有单独的 pair sampling seed。后续启动命令仍需显式写出 model seed，不能依赖配置文件默认值。

### 4.2 运行顺序

每个 seed 运行一对实验：先 Baseline，再 UniGIR，或者在两张 GPU 上分别启动两个独立实验。每个实验必须有独立的 root、日志目录、checkpoint 目录和最终结果文件。SSH 启动使用脱离会话的方式，标准输出和标准错误分别或合并重定向到该实验的日志文件。

winpc 使用 `run_scripts/winpc_schedule_mosi_experiment.ps1` 注册一次性计划任务，再由任务调用 `winpc_mosi_unigir_smoke.ps1`。任务名、运行名、日志目录和 checkpoint 目录必须按 seed 与方法区分。

如果任务中断，重新连接后先检查进程、日志末尾和 `last.ckpt`，再使用自动恢复逻辑继续。不能直接删除旧目录重跑，也不能用新目录掩盖中断原因。

### 4.3 G3 判定方式

三个 model seed 完成后，统一报告每个 seed 的 acc@1、ROC AUC、四个任务的平均指标、均值、标准差和 UniGIR-Baseline 的逐 seed 差值。

| 判定 | 条件 |
|---|---|
| 支持进入 G0 | ROC AUC 的平均差值为正，acc@1 的平均差值为正，且至少 2/3 个 seed 在两个主指标上同时不低于 Baseline |
| 结果不稳定 | 平均差值为正，但只有 1/3 个 seed 同时取得双指标优势，或不同 seed 的方向变化明显 |
| 暂停主线 | ROC AUC 或 acc@1 的平均差值不为正，且至少 2/3 个 seed 同时退化 |

这一步不选择最好的 seed 作为最终结果。所有 seed 都必须进入表格。

| model seed | Baseline acc@1 | UniGIR acc@1 | acc@1 差值 | Baseline ROC AUC | UniGIR ROC AUC | ROC AUC 差值 |

## 5. G4-G0 正式确认协议

### 5.1 第一轮只做 10 epoch

G0 第一轮使用 10 epoch，目的是用完整封存数据检查方法优势能否重现，同时控制共用 GPU 的占用时间。当前不直接启动 100 epoch。只有第一轮结果支持核心假设，并且日志、checkpoint 和评测流程没有问题，才讨论是否增加 100 epoch 作为补充实验。

### 5.2 固定参数

| 项目 | 固定值 |
|---|---|
| 数据根目录 | `trifeatures_g0_seed20260924` |
| train pair 上限 | `10000`，使用 G0 全部可用训练数据范围 |
| test pair 上限 | 按当前数据模块的固定 test 配置执行，不中途调整 |
| batch size | 64 |
| embedding dim | 256 |
| mask 数量 | 3 |
| mask ratio | 0.7 |
| 训练 epoch | 10 |
| model seed | 42、7、123 |
| pair sampling seed | 固定为 42 |
| Baseline | 当前冻结的 Baseline 配置 |
| UniGIR | prototype 数 128，queue size 1024，loss weight 0.25，one-way，cross 关闭 |
| linear probing | 开启，`frequency=by_fit` |
| checkpoint | 每个 epoch 保存 `last.ckpt`，每个 seed 和方法独立目录 |
| 评测 | 全部训练完成后统一运行最终 test 评测 |

Baseline 与 UniGIR 必须使用相同的数据根目录、pair sampling seed、model seed 列表和训练预算。只有方法本身的差异可以改变。

### 5.4 G0 主要指标

G0 的主要指标在协议冻结后固定为 synergy ROC AUC。保护指标为 synergy acc@1，辅助指标为 share、unique 以及四个任务的平均 acc@1 和平均 ROC AUC。结果表必须同时包含：

- Baseline 与 UniGIR 的逐 seed 原始值；
- 每个 seed 的差值；
- 三个 seed 的均值和标准差；
- 成功完成、异常退出、恢复次数和最终 checkpoint 路径；
- 数据生成 seed、pair sampling seed、model seed、代码版本和运行环境。

### 5.5 G0 判定方式

| 判定 | 预先定义的条件 | 后续动作 |
|---|---|---|
| Strong Go | synergy ROC AUC 在 3/3 个 seed 上提升，且平均提升至少 0.01；保护指标没有明显整体退化 | 进入表示分析和必要的补充消融 |
| Weak Go | synergy ROC AUC 平均提升，且至少 2/3 个 seed 提升，但未达到 Strong Go | 保留主线，先检查 seed 方差，再决定是否增加 100 epoch |
| Uncertain | 平均提升很小、方向不稳定，或主要指标与保护指标方向冲突 | 暂停大规模训练，优先做误差和表示层分析 |
| No-Go | synergy ROC AUC 平均不提升，或至少 2/3 个 seed 退化并伴随保护指标下降 | 停止当前 UniGIR 主线，整理失败原因 |

阈值用于提前规定判断方式，不能在看完结果后更换为对自己有利的标准。
