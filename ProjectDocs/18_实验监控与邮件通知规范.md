轻薄本只负责 SSH、读取日志、CPU 统计和发送邮件。训练和 checkpoint 评测都在 `winpc` 上运行，轻薄本不会被当作实验机器使用。后续每组 `winpc` 实验都应使用独立配置、独立任务名、独立目录和邮件 watchdog；只有在 GPU 归属明确且前一项成功时，才自动启动串行队列的下一项。

## 每个实验必须具备的目录

同一组实验中的每个 run 都必须有独立的：

| 内容 | 规则 | 作用 |
|---|---|---|
| 运行目录 | `RunRoot/RunName/` | 保存 Lightning 输出和 checkpoint |
| checkpoint | `RunRoot/RunName/checkpoints/last.ckpt` | 判断任务是否真正完成，也用于断点续跑 |
| 状态日志 | `LogRoot/RunName.status.log` | 保存实际参数、启动时间和 `END EXIT_CODE` |
| 标准输出 | `LogRoot/RunName.stdout.log` | 保存训练和最终 probing 输出 |
| 标准错误 | `LogRoot/RunName.stderr.log` | 保存 CUDA、数据和 Python 错误 |
| watchdog 状态 | `LogRoot/<ExperimentName>.watchdog.*` | 保存当前动作、事件和邮件结果 |

`RunName`、任务名和 checkpoint 路径不能在不同实验之间复用。这样即使某一项失败，也不会覆盖以前的日志和 `last.ckpt`。

## watchdog 的检查顺序

Windows 计划任务每 15 分钟运行一次 watchdog。每次运行按以下顺序处理：

1. 读取每一项的状态日志、标准输出、标准错误和 checkpoint。
2. 检查是否出现非零退出码、CUDA error、显存不足、Python traceback 或 checkpoint 缺失。
3. 调用 `nvidia-smi`，识别当前 GPU 计算进程。当前实验自己的进程和 Windows 桌面进程可以通过；无法确认归属的进程会触发 `STOP`。
4. 检查串行顺序。前一项没有成功时，后面的任务即使已经存在，也不会继续推进。
5. 前一项成功、当前 GPU 安全且下一项尚未注册时，才注册下一项 Windows 计划任务。
6. 将完整状态写入 JSON，并发送邮件。

watchdog 不会停止已有训练，不会删除任务，不会删除日志或 checkpoint。遇到异常时只写 `STOP` 和邮件，下一步由我读取原因后决定。

## 邮件规则

发信程序为 `run_scripts/winpc_g4_notify.py`，账号、授权码和收件地址只从环境变量读取：

- `INF_MASKING_MAIL_SMTP_HOST`
- `INF_MASKING_MAIL_SMTP_PORT`
- `INF_MASKING_MAIL_SENDER`
- `INF_MASKING_MAIL_PASSWORD`
- `INF_MASKING_MAIL_RECIPIENT`

winpc 的环境变量文件放在用户目录下的 `secrets/InfMasking/mail.env.ps1`，不进入 Git。轻薄本使用同一套发信逻辑，但本地密钥文件只保存在被 `.gitignore` 忽略的文件中。

正常运行时发送：

| 事件 | 邮件 |
|---|---|
| 仍有任务运行或等待 | 每次 15 分钟检查都发送 `WAIT` |
| 启动下一项 | 立即发送 `START_REQUESTED` |
| 非零退出、错误标记、checkpoint 缺失或 GPU 归属不明 | 立即发送 `STOP` |
| 全部完成 | 只在第一次进入 `ALL_COMPLETE` 时发送一次 |
| 邮件本身发送失败 | 写入 watchdog 邮件错误日志，不中断训练 |

旧版 G0 watchdog 之前会在每次 15 分钟检查时重复发送 `ALL_COMPLETE`。通用版本已经改为只在状态第一次变为 `ALL_COMPLETE` 时发送，避免完成后继续打扰。

## 启动方式

新实验先复制 `winpc_experiment_watchdog.config.example.json`，改成独立的 `ExperimentName`、任务名、运行名、数据目录和参数。确认配置、代码和数据清单后，在 winpc 上用脱离 SSH 会话的 Windows 计划任务运行 watchdog。

计划任务的动作应调用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File `
  C:\path\to\run_scripts\winpc_experiment_watchdog.ps1 `
  -ProjectRoot C:\path\to\InfMasking `
  -ConfigPath C:\path\to\run_scripts\my_experiment.watchdog.json
```

训练任务仍由 `winpc_schedule_experiment.ps1` 创建，并由 `winpc_start_experiment.ps1` 写入独立日志。SSH 断开不会影响已经注册的计划任务。

## 当前验证结果

- G0 六项任务均以 `EXIT_CODE=0` 结束并生成 `last.ckpt`。
- winpc 最近一次 watchdog 状态为 `ALL_COMPLETE`，通知状态为 `EMAIL_SENT`。
- G0 unique2 的四项只读 checkpoint 评测均以 `EXIT_CODE=0` 完成，队列状态为 `QUEUE_COMPLETE`，每项开始和结束邮件均发送成功。
- winpc 的 GTX 1080 Ti 在评测结束后没有训练任务；`nvidia-smi` 只看到 Windows 桌面进程和评测 Python 进程，评测队列结束后 GPU 释放。
- 轻薄本的 `uv` 已能使用独立的 uv Python 3.13.11 发送通知。项目原 `.venv` 指向已失效的 Python 安装，因此本轮没有用它运行任何训练。

## 仍需人工确认的地方

配置驱动 watchdog 能检查任务、日志和 GPU，但它不能判断研究结果是否达到 Go 条件，也不能从 `acc_per_class` 自动推断语义类别。每一组实验结束后仍需要读取结果、核对配置和更新 `ProjectDocs/03_实验记录.md`、`04_结果分析.md` 及导师汇报文档。当前 G0 独立评测发现 unique2 的配对 acc@1 在三个 seed 上均下降，下一项应该先固定 test transform 并复核，不应直接增加训练并行度。
