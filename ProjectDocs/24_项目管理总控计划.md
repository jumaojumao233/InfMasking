# InfMasking / UniGIR 项目管理总控计划

更新时间：2026-09-26

## 0. 当前阶段：先验证融合关系结构现象

V2-Cosine 已有 G0 synergy 正向信号，同时伴随 unique2 下降；V3-Geodesic 的两个完成运行没有解决这个权衡。当前不继续堆叠方法，而是执行阶段 1 融合关系结构失真诊断：固定 G0 InfMasking checkpoint，在测试时改变遮挡比例，比较完整融合表示和 masked 融合表示的样本关系。

这一阶段的直接测量对象是融合表示关系结构，不能写成已经测到协同结构。阶段门是：关系指标是否随遮挡稳定变化、是否跨 mask seed 稳定、以及这种变化是否能和样本自身表示漂移区分。详细协议见 [`25_阶段1融合关系结构诊断计划.md`](25_阶段1融合关系结构诊断计划.md)。在阶段 1 结果出来前，不实现 V4，不扩大 V3，不启动 100 epoch。

## 1. 项目定位

当前仓库以 InfMasking 为基线，研究扩展 UniGIR：使用完整多模态视图到 prototype 的关系轮廓，约束掩码视图保留更完整的多模态信息。

项目已经越过环境搭建和基本可运行阶段。数据生成、训练、checkpoint、linear probing、Windows 计划任务、watchdog、G0 正式确认、MOSI、机制诊断和 V3-Geodesic 原型都已有实现或实验记录。当前管理重点是筛选研究结论、关闭未完成实验、冻结证据和控制继续投入的上限。

## 2. 当前事实基线

以下内容来自仓库记录和本轮对 winpc 的只读核查。

1. UniGIR V2-Cosine 已完成主要三 seed 验证。G0 synergy ROC AUC 三个 seed 均上升，平均变化为 `+0.026`；unique2 Acc@1 三个 seed 均下降，平均变化为 `-0.053`；四任务平均 Acc@1 变化为 `-0.010`，平均 AUC 变化为 `+0.003`。
2. MOSI 三个 seed 的 Acc 和 AUC 均有正向变化。MOSI 只能支持真实任务迁移，不能单独证明 synergy 机制。
3. 已有梯度诊断不支持稳定、全局的 profile/base 梯度冲突。24 个 batch 中，profile/base 梯度范数比约为 10%—19%，seed=7 和 seed=123 存在部分冲突 batch。该结果是局部证据。
4. V3-Geodesic 修复了 Sinkhorn 指数化下溢。seed=42 的有效短跑中，V3 相对 V2 的四任务平均 Acc/AUC 为 `-0.0229/-0.0079`，synergy AUC 为 `-0.0229`，unique2 Acc 为 `-0.0316`。
5. V3 seed=7 曾在 epoch 7 附近发生 CUDA illegal memory access。阻塞式 8 epoch 诊断和生产形状 forward/backward 诊断均通过，没有稳定复现原错误。
6. V3 seed=7 严格复跑已于 `2026-09-26 17:10:11` 以 `EXIT_CODE=0` 完成；10 epoch、四项 linear probing、checkpoint 和 TensorBoard 均存在，stderr 没有 CUDA error，GPU 已空闲。该运行开启了 `CUDA_LAUNCH_BLOCKING=1`，与 V2 的执行时序不同。
7. 当前架构依赖方向为入口 → 配置与数据 → 模型 → 损失 → 可选 UniGIR 分支；评测只读模型表征接口。现有架构说明未发现生产模块循环依赖。

## 3. 我的判断

### 3.1 研究判断

V2 已经产生可重复的 synergy 正向信号，但同时存在稳定的 unique2 代价。当前证据更像信息方向的再分配，而不是整体表征质量的无条件提升。论文如果继续，核心问题必须写成：关系轮廓为何提高某类协同信息，以及为什么会损伤某类独有信息。

V3 在当前 seed=42 协议下没有修复这个矛盾，且性能低于 V2。测地距离本身也已有接近的相关工作背景。因此 V3 目前适合作为受控负向对照，不适合作为默认主线，也不值得开展 graph、temperature、EMA、queue 和 loss weight 的联合搜索。

V4 仍是未验证假设。当前实现 V4 会扩大变量数量，降低归因能力，并推迟论文证据冻结。M1 决策门完成前不实施。

### 3.2 工程判断

工程链路已经足够支撑短预算研究验证。当前工程瓶颈是状态源过多：`progress.md`、研究总览、实验记录、结果分析、Agent 接续说明和任务线程都包含状态，且部分旧结论仍保留。后续必须指定本文件为项目决策入口，实验事实仍写入 `03_实验记录.md`，解释写入 `04_结果分析.md`。

### 3.3 投稿判断

目前还不能宣称形成稳定的 CCF-A 主会论文方案。能继续，但有条件：需要冻结一个清楚的主张、给出 synergy/unique2 权衡的机制证据、证明真实任务收益不是单个数据集或单个 seed 偶然，并完成独立数字审计。条件越多，越不可靠，因此每个阶段设置停止条件。

## 4. 目标与非目标

### 目标

- 关闭所有悬而未决的实验状态；
- 在 V2、V3 和停止研究之间做一次有证据的选择；
- 固定论文主张、主表、消融、机制分析和复现实验清单；
- 让任一新 Agent 只读本文件、架构说明、实验记录和结果分析即可接手；
- 控制 GPU、时间、存储和 token 投入。

### 非目标

- 不为了得到正结果搜索大量超参数；
- 不在现有阶段实现 V4；
- 不把中间 checkpoint、失败运行或单 seed 结果写进主结论；
- 不启动 100 epoch 或新增大数据集，除非前一阶段门通过；
- 不改动与当前决策无关的模块。

## 5. 里程碑与阶段门

### M0：关闭当前运行

输入：V3 seed=7 严格复跑目录、状态日志、stderr、checkpoint 和 TensorBoard。该阶段已完成。

动作：只读核对 `END`、退出码、第 10 个 epoch、linear probing、checkpoint 完整性和 GPU 释放状态。失败时保留现场，不恢复失败 checkpoint，不重复无差别重跑。

验收：已得到成功状态；status 日志含 `END ... EXIT_CODE=0`，stdout 完成四项 probing，checkpoint 和 TensorBoard 存在，GPU 已释放。

### M1：V3 去留决策

输入：V3 seed=42 有效结果、V3 seed=7 最终结果、对应 V2 配对结果。

阶段门：

- 若 seed=7 再次出现 CUDA 非零退出，停止 V3 性能扩展，V3 只保留为工程失败记录；
- 若 seed=7 成功但 V3 仍未同时改善 synergy AUC 和 unique2，停止 V3，保留为负向对照；
- 若 seed=7 出现单次正向结果，只允许一次预先固定的确认 seed，不允许同时改超参数；
- 只有至少两个有效 seed 显示方向一致、且没有明显四任务平均性能代价，才讨论 V3 进入论文主线。

### M2：论文主张冻结

候选主线默认是 V2-Cosine。需要回答三个问题：

1. synergy 改善是否跨 seed、跨数据协议成立；
2. unique2 下降是稳定权衡、评测噪声，还是表示几何变化；
3. profile 内容是否真的有用，而不是额外正则、queue 或训练预算造成。

验收：形成一句可以被实验反驳的主张；每个主张映射到主表、消融或机制图；删去没有证据支持的贡献表述。

### M3：证据包冻结

冻结内容：代码 commit、Git diff、配置、数据根目录和哈希、model seed、pair seed、运行命令、退出码、checkpoint、TensorBoard、主指标和聚合脚本。

验收：主表数字可从原始产物复算；失败运行不进入均值；开发 split 与正式确认 split 明确分开；结果表、图、图注和导师汇报数字一致。

### M4：论文与独立审计

先写结果和限制，再写方法包装。独立审计由新窗口、不同模型或人工完成，主 Agent 不在同一上下文中把自审写成可靠性证明。

验收：审计者能够只凭固定入口重算关键表格，指出至少一个潜在反例或测试盲区；发现数字或协议不一致时退回 M3。

## 6. 项目节奏

每次只允许一个活动实验。每轮任务包含：开始记录、只改必要文件、轻量验证、结果落盘、阶段门判断、下一步唯一行动。监控任务只在状态变化、完成、失败或需要用户决策时通知。

近期顺序固定为：

1. 完成 M0，关闭 V3 seed=7 严格复跑；
2. 完成 M1，决定停止 V3 或只做一次受限确认；
3. 更新研究总览、实验记录、结果分析和 Agent 接续说明；
4. 进入 M2，冻结 V2 的论文主张和证据缺口；
5. 只补能改变投稿决策的最小实验；
6. 冻结证据包并安排独立审计。
