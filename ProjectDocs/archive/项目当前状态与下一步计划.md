- # InfMasking / UniGIR 项目当前状态与下一步计划
  更新时间：2026-09-10

  项目目标：以 InfMasking（NeurIPS 2025 Spotlight）为基础，研究面向多模态自监督学习的全局关系结构目标，暂定方法名为 UniGIR，目标投稿 ACM Multimedia 2027。

  | 事项                   | 状态   | 当前说明                                                     |
  | ---------------------- | ------ | ------------------------------------------------------------ |
  | InfMasking 基线复现    | 已完成 | Windows + CPU 环境下跑通数据生成、训练、下游评测和 checkpoint 保存 |
  | UniGIR V2 实现         | 已完成 | 在损失函数中加入原型轮廓对齐分支，默认配置可以运行           |
  | Trifeatures 短训练对照 | 已完成 | R-U 组和 S 组各完成 Baseline、UniGIR 两组实验，均为 4 epoch、seed 42 |
  | 机制内部指标验证       | 已完成 | 原型分配预测准确率随训练上升，训练过程没有出现 NaN           |
  | 长训练结论             | 未完成 | 目前没有 30 至 100 epoch 级别的结果，无法判断 V2 是否能带来稳定的协同增益 |

  ## 二、已经完成的工作
  1. 我完成了 Python 环境搭建。原项目依赖主要面向 Linux 和 conda，在 Windows 上直接安装存在版本和网络问题；目前已使用本地虚拟环境完成依赖安装，PyTorch CPU 版本可以正常导入。
  2. 我完成了基础代码的本地适配。硬编码的 `.cuda()` 调用已改为跟随实际设备，数据集路径已改为本地路径，运行日志统一使用 UTF-8，代码可以在无 GPU 的环境下运行。
  3. 我准备好了 Trifeatures 合成数据集。当前本地数据包含 2400 张训练图和 200 张测试图，数据生成和读取流程已经验证。
  4. 我跑通了 InfMasking 基线的端到端流程，包括自监督训练、四个下游任务的 linear probing、checkpoint 保存和 TensorBoard 事件记录。训练 loss 能够下降，评测输出格式正常。
  5. 我完成了 CPU 性能测量。当前配置下单个训练 step 约 36 秒，单个 epoch 约 1.5 至 1.6 小时；按论文规模进行 100 epoch、多 seed 实验，在本机 CPU 上代价过高。因此后续先采用 embed_dim 256、batch size 32 的减配配置做诊断，完整结论仍需要 GPU。
  6. 我实现了 UniGIR V2。V2 不改变编码器和投影头，只在 `InfMaskingLoss` 中增加可选的全局原型轮廓对齐分支。当前配置使用原型数 $K=512$、投影维度 $d=256$、掩码视图数 $T=6$、温度 $\tau=0.1$，原型更新率 $\eta=0.05$。关闭该分支时，原有 InfMasking 行为保持不变。
  7. 我修复了 V2 实现过程中的两个问题：原型 EMA 更新和自动求导之间的原地修改冲突，以及 Hydra 配置键结构问题。当前版本能够完成训练和验证，并且不会用验证集更新原型库。
  8. 我完成了论文和方法定位的调整。原先考虑把测地距离作为主要卖点，但 GeoMM（CVPR 2025）已经发表了相近做法。因此当前定位改为全局关系结构感知的协同学习，测地距离暂时降为后续增强版本或对照项。
  9. 我整理了实验日志和研究文档。详细实验数据、路线规划、运行过程和 idea 修订记录均已保存在 `docs/` 目录中。

  ## 三、当前方法和实验结果
  V2 对完整视图表征 $z$ 和原型矩阵 $P\in\mathbb{R}^{K\times d}$ 计算相似度，再通过 Sinkhorn 迭代得到完整视图的均衡原型分配 $q$。对第 $t$ 个掩码视图，模型输出原型分布 $p_t$：

  $$
  s = zP^{\mathsf T}, \qquad
  q = \operatorname{Sinkhorn}\left(\exp\left(\frac{s}{\varepsilon}\right)\right), \qquad
  p_t = \operatorname{softmax}\left(\frac{m_tP^{\mathsf T}}{\tau}\right).
  $$

  其中，$m_t$ 是第 $t$ 个掩码视图的表征，$q$ 从计算图中分离，作为完整视图提供的伪标签。轮廓对齐损失为：

  $$
  \mathcal{L}_{\mathrm{profile}}
  = \frac{1}{T}\sum_{t=1}^{T}
  \operatorname{KL}\left(q\,\|\,p_t\right).
  $$

  原型不通过梯度更新，而是使用当前 batch 的完整视图表征做 EMA 更新：

  $$
  P \leftarrow
  \operatorname{Normalize}\left(P+\eta q^{\mathsf T}z\right).
  $$

  短训练结果如下。所有结果均为 seed 42、4 epoch、`max_size=1024`，在 CPU 上完成。

  | 数据组              | Baseline 平均 acc@1 | UniGIR 平均 acc@1 |   差异 |
  | ------------------- | ------------------: | ----------------: | -----: |
  | R-U，`biased=false` |               0.372 |             0.355 | -0.017 |
  | S，`biased=true`    |               0.375 |             0.345 | -0.030 |

  目前能确认两件事：
  1. V2 的原型分配目标确实在学习。R-U 组的原型预测准确率从 0.159 上升到 0.373，S 组从 0.241 上升到 0.350；训练过程稳定，没有 NaN。
  2. 短训练下游指标没有增益，且两组方向都略低于 Baseline。但 4 epoch 太短，S 组的 synergy 任务也基本处于随机水平，现有结果不足以证明 V2 无效，也不足以证明 V2 有效。

  因此当前最准确的结论是：机制已经实现并产生了学习信号，但方法是否能改善协同信息建模，还需要更长训练和多 seed 验证。

  ## 四、接下来的计划
  ### 第一阶段：固定当前版本并完成低成本诊断
  1. 整理当前代码、配置、数据生成命令和实验日志，固定一个可复现的基线版本。
  2. 跑通 InfMasking 的 CPU 减配基线，确认 embed_dim 256、batch size 32 的训练和 probing 流程没有新的问题。
  3. 在减配配置下做低成本诊断，优先比较以下因素：
     - 是否加入 $\mathcal{L}_{\mathrm{profile}}$；
     - profile loss 的权重；
     - 原型数 $K$；
     - 单向轮廓预测和双向轮廓预测。
  4. 记录每组实验的训练 loss、原型预测准确率、share、unique 和 synergy 指标，先判断趋势，再决定是否继续扩展方法。

  ### 第二阶段：有 GPU 后完成关键验证
  1. 在 S 组上跑 Baseline 与 UniGIR 的长训练对照，建议至少覆盖 100 epoch 和 3 个 seed。
  2. 对最佳 checkpoint 重新进行四个下游任务的 probing，重点观察 synergy 是否稳定高于 Baseline，而不是只看单个 epoch 的结果。
  3. 如果 V2 在长训练下有稳定增益，再做 profile loss 权重、$K$、$\tau$ 和 cross 选项的消融。
  4. 如果 V2 长训练仍无增益，优先检查全局轮廓目标是否和现有掩码损失重复，再决定是修改目标形式还是停止这条方法线。

  ### 第三阶段：扩展到真实数据和论文材料
  只有在 Trifeatures 上得到明确结论后，我再进入 MultiBench、MMIMDb 等真实数据集，补充数据许可、训练配置、可视化和与已有方法的对比。测地距离版本 V3 暂不优先实现，避免在 V2 的核心假设尚未验证前继续扩大工程量。

  ## 拿不准的点
  ### 1. CPU 减配和 GPU 长训练的先后顺序
  目前 CPU 减配实验可以立即开始，但它不能替代论文规模的长训练。希望导师确认：
  - A：先按当前计划完成 CPU 减配诊断，等 V2 方向更明确后再申请 GPU。
  - B：优先解决实验室 GPU 或云 GPU，直接跑 S 组长训练，CPU 只做必要的代码检查。
  - C：暂时不做长训练，先把现有复现和短实验整理成阶段性报告。

  ### 2. V2 的方法路线
  当前 V2 的内部学习信号正常，但短训练没有下游增益。希望导师确认：
  - A：先不改方法，优先用长训练判断 V2 是否成立。
  - B：先做 profile loss 权重、$K$ 和双向预测的低成本消融。
  - C：重新检查全局轮廓目标是否与 InfMasking 原有损失重复，并考虑更换目标形式。

  ### 3. 后续研究范围
  目前继续扩展需要在验证 V2、实现 V3、准备真实数据和整理论文材料之间分配时间。希望导师确认：
  - A：集中验证 Trifeatures，得到明确的正结果或负结果后再扩展。
  - B：验证 V2 的同时准备真实数据集和实验脚本，减少后续等待。
  - C：如果 V2 长训练仍无效，及时收缩或更换方法方向，不继续投入 V3。
