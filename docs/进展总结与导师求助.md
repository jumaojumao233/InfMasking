## 三、方法细节：原型轮廓对齐里两个关键机制

新损失包含三个技术环节：轮廓如何计算（Sinkhorn 均衡分配）、原型如何更新（EMA）以及如何利用历史特征（feature queue）。本节说明三者的做法和理由，以及损失如何组织。

### 3.1 要解决的问题

InfMasking 原有的损失只回答一个问题：掩码视图和完整视图像不像（InfoNCE 和掩码分布匹配都在 batch 内做）。它不回答另一个问题：这个样本在整批数据的结构里处于什么位置。设想一个有 100 类的数据集，模型能把残缺输入和完整输入对上，却不知道残缺输入属于哪一类——因为损失里从来没有出现类这个概念。

我们想加的就是这个概念：给模型一组参照点，让它学会报出残缺输入相对这些参照点的位置。参照点就是原型（prototype），一组与投影头输出同维的向量。每个样本的全局描述定义成它对 K 个原型的软分配，即一个 K 维概率分布，下文叫轮廓。

### 3.2 Sinkhorn 均衡分配：轮廓怎么算

对完整视图表征 z（256 维、L2 归一化），先算它与 K 个原型的相似度，得到一个 K 维得分向量。直接对这个向量做 softmax 得到轮廓会有问题：训练早期模型还没有区分度，softmax 会很快退化成把绝大多数样本分到同一个原型，原型失去意义（业内叫分配塌缩）。

Sinkhorn-Knopp 迭代是防塌缩的标准做法：把整批样本的得分拼成 B×K 的矩阵，交替做行归一化和列归一化，迭代三轮。行归一化保证每个样本的轮廓是合法的概率分布；列归一化保证每个原型在这一批里大约分到等量的样本。两步交替的结果是：这批样本被尽量均匀地摊到全部 K 个原型上，而不是挤成一团。这个摊开的分布 q 从计算图中 detach，作为伪标签，不参与反向传播。

K=512 时随机猜中一个原型的概率约 0.2%。实验里这个指标从 0.15-0.24 涨到 0.35-0.37，说明分配在学习，没有塌缩。

### 3.3 EMA 更新：原型怎么跟着模型走

原型与可训练参数分开管理。它们不接收梯度，每个训练步用本批完整视图的表征做一次滑动平均更新：

原型 = L2归一化( 原型 + η × 本批样本按其分配加权的均值 )

η 取 0.05。也就是说原型是训练过程中逐步移动的质心，始终和当前的特征空间保持一致。

选 EMA 而不是离线聚类，原因有两个。一是编码器从头训练，特征空间一直在动，离线算一次的原型很快过时；如果每个 epoch 全量重算，代价又回到 O(n²)。二是原型不进反向传播，就不和主损失抢梯度，训练更稳。

### 3.4 损失怎么把三者接起来

训练时每个样本有 1 个完整视图和 6 个掩码视图。完整视图算出轮廓 q（经 Sinkhorn、detach）。计算 q 时还会加入最近保存的完整视图特征，以减少单个 batch 的影响。每个掩码视图对自己的 K 维得分做 softmax 得到 p_t。损失是 p_t 与 q 的 KL 散度，6 个掩码视图平均，两组增广各算一次：

L_global = KL( q_完整 ‖ p_掩码 )

梯度只经过 p 这一侧回到掩码视图的编码器。语义是：残缺输入给出的全局位置分布，必须和完整输入一致。总损失采用显式权重：

$$
\mathcal{L}
=
\mathcal{L}_{\mathrm{InfMasking}}
+
\alpha\mathcal{L}_{\mathrm{profile}}.
$$

当前配置取 $\alpha=0.25$，开关和权重都在配置里可调。

### 3.5 与同类做法的关系

Sinkhorn 均衡分配加 EMA 原型最早来自 SwAV（NeurIPS 2020），我们不是声称发明这两个机制。差异在于用途：SwAV 让同一张图的两个裁剪对齐到同一原型，处理的是单模态的视图不变性；这里对齐的是残缺多模态输入与完整多模态输入，且轮廓是显式的训练目标而不是辅助正则。和最初的设想（idea.md 里冻结预训练编码器离线 k-means）相比，在线方案不需要任何预训练模型，这正好适配从零训练的多模态库。

## 四、对照实验数据

实验设置：seed 42，4 个 epoch，训练对 1024，batch 64，embedding 512，掩码率 0.7，掩码视图 6 个。本机 CPU，单组约 1.5-2 小时。评测沿用 InfMasking 官方的 linear probing 流程，报告下游四个任务各自的 acc@1，最后一行是四任务平均。任务构成：share 为两图共享的形状属性（10 类）；unique1/unique2 为两图各自的纹理属性（各 10 类，同一属性分属两张图）；synergy 为二分类，判断纹理-颜色组合是否符合训练时的人为相关（随机水平 0.50）。

解读：

2. share 与 unique 列：两组方法都能随训练上升，趋势正常；UniGIR 与 Baseline 逐任务互有高低，均值差 0.02-0.03，方向性略低。单次 probing 的抖动约 ±0.05，单看任何一格都没有统计意义，但两组同向，不能只说是噪声。
3. 内部指标（仅 UniGIR 有）：掩码视图预测完整视图原型分配的正确率，K=512 时随机水平约 0.2%。R-U 组从 0.159 涨到 0.373，S 组从 0.241 涨到 0.350。这个目标本身在学，训练也稳定，说明不是没有信号，而是信号没有转化为下游指标。

## 五、当前判断

1. 新加的目标在学习，训练稳定，没出现 NaN 或崩溃。这一点是干净的。
2. 下游指标没有增益，两组都略低于 Baseline（差 0.02-0.03）。单次 probing 的抖动在 ±0.05 量级，单看一个数不足以说输，但两组同向，我不再把差异归结为噪声。
3. 由此还下不了最终结论，原因在数据本身：synergy 是 S 组唯一能体现协同信息差异的任务，而它需要长训练才浮现。官方论文是 100 个 epoch 后 synergy 到 0.77。4 个 epoch 里它基本不动，所以 V2 是否真的没用，当前实验回答不了。
4. 资源是硬约束。本机无 GPU，CPU 实测单训练步约 36 秒，100 epoch 一组要 40 小时以上，跑多组不现实。想要一个有定论的回答（无论正负），需要 GPU 上跑 100 epoch 的 S 组对比加几组 seed。

## 六、2026-09-10 的实现调整

针对短训练中下游指标没有增益的问题，我先进行了低成本的代码调整，暂不启动长训练。

1. 在原型模块中加入跨 batch feature queue。当前完整视图会和最近保存的历史完整视图一起参与 Sinkhorn 分配，queue 长度在 UniGIR 默认配置中设为 1024。验证阶段不更新 queue。
2. 将 profile loss 改成显式权重，当前形式为 $\mathcal{L}=\mathcal{L}_{\mathrm{InfMasking}}+\alpha\mathcal{L}_{\mathrm{profile}}$，默认 $\alpha=0.25$。这样可以直接比较不同权重，不再受损失项数量影响。
3. 增加 profile KL、原型使用熵和 active prototypes 等指标，用于判断原型是否塌缩，以及 profile 学习信号是否真正稳定。
4. 增加 `enable_linear_probe=false` 开关，并准备低成本诊断脚本。短实验可以只训练自监督目标，完成后再对少数候选模型进行 probing。

代码差异检查已通过。运行时测试尚未完成，原因是当前 Windows 无法创建新的 Python 子进程，错误发生在启动解释器阶段。相关代码和诊断脚本已经保留，待解释器可以正常启动后先完成 queue、EMA、反向传播和小规模消融测试。

### Q2：方法本身的下一步怎么走

- A：优先解决算力问题，拿到 100 epoch 的 S 组对比再决定要不要调
- B：先不调 V2，回头检视问题本身——如果全局结构目标与掩码自监督冗余，应该换一个与现有损失互补的目标形式
